Accessibility fixes in the parts

12 changes

Everything in this release

  • A full accessibility check of every part page, in light and dark, found nine kinds of problem. All are fixed. The outline editor's slides are list items, not groups, so a screen reader reads them as a list. The section lane no longer puts a status region inside its listbox, and says when a section starts generating through its own message. The order ticket's summary is a valid description list. The heatmap's direction values sit on a light tag, so they pass 4.5:1. The transcript's timestamps and the layout alternatives' figure use text colours that pass 4.5:1.Updated
  • Scrolling areas can be reached with the keyboard: the ticker tape when motion is reduced, the sheet's body, the prompt index, the glance panel where it scrolls, and the example threads in the docs. Headings are in order: the canvas panel's title is a second-level heading, and a template with no title has no empty first-level heading.Updated
  • The prompt box grows with its text, so the words are not clipped when people increase the line spacing.Updated
  • Every part's page now shows a Do picture and an Avoid picture side by side, each with a one-line caption. Before, only 16 parts had them; now all 211 do. Each pair is built from the real part, so it stays in step with the code, and each Avoid shows the one mistake that part's own guidance warns about, such as two main buttons competing, a progress bar in amber when nothing needs doing, or a whole rewrite offered as one suggestion.New
  • Where the real part cannot show the mistake (it always draws its own label, or always asks first), the Avoid picture is a plain stand-in built from the same tokens, and the caption says so when the whole screen is only a sketch. Parts that open over the page (dialogs, sheets, menus, tooltips, the command palette) are drawn open in place instead, so they do not cover the page.New
  • New check for whoever builds Tattva: check:do-avoid opens every part's Usage tab and fails if a part has no pair, a picture is empty or wider than its frame, a caption is not plain and short, or the page logs an error. Its contact sheets (eight parts per image) are the quickest way to look the whole set over.New
  • Twelve parts now move keyboard focus themselves when the control you pressed goes away, instead of leaving it to the app. ToolChip, AttachmentChip, ContextPill and SuggestionCard move to the next item (or the previous one, or the message box) after Remove, Accept or Dismiss. MemoryList returns to the Edit button after Save and to the next memory after a delete. CheckpointList moves into the confirm step and back on Cancel. SuggestionBar follows its buttons and returns to the document after Keep or Discard. VersionHistory moves to the restored version. CanvasPanel returns to what opened it after Close. StarterGallery moves to the message box once a choice is made. Each has a prop to choose a different place.Updated
  • Changes that matter are now read out by the part itself, and nothing is read when it first appears: an upload finishing or failing (AttachmentChip), a memory deleted (MemoryList), a version restored (VersionHistory) or changed (CanvasPanel), new templates after Shuffle (StarterGallery), options generating and arriving (VariantGrid), and generating starting and ending (PromptBox). Every message can be reworded or translated.Updated
  • CanvasPanel's content can now be reached with Tab and scrolled with the arrow keys. ContextPill's clear button can be named for what it clears (clearLabel). The parts' accessibility notes say what each part now does, and the list of what you still have to do is shorter.Updated
  • The Figma plugin has a new tab, Insert parts. It adds a part to your file as a real Figma component, with each documented example as a variant (Button has Variant and Size, Badge has Tone, Approval prompt has Risk). Spacing and padding use auto layout wherever it matches the code; text keeps its styles; icons are vectors; and 98.6% of colours are linked to the Tattva variables, so switching theme or Light and Dark recolours the part. The free plugin has the 63 free parts and lists the Pro parts; Tattva Pro for Figma, with all 211 parts, is in the Pro download.New
  • The parts are copied from how each one draws in the browser, so the Figma copy and the code never drift apart. Native controls the browser draws itself (sliders, checkboxes, progress bars) and images come across as exact pictures. Hover and focus looks and animations are not copied.New
  • New checks for whoever builds Tattva: capture-figma records every part from Storybook, and check-figma-fidelity redraws each of the 580 variants the way Figma builds them and compares it with the real part, pixel by pixel: 565 are within 4%, and none is more than 12% off. check:plugins now builds every part in a strict stand-in for Figma.New

Earlier releases

  • v0.16Plugins for Claude Code and Figma+
    • Claude Code plugin. Inside Claude Code, type /plugin marketplace add LKB00/tattva, then /plugin install tattva@tattva. It connects the Tattva MCP server, adds a skill that teaches Claude to find, read and review real Tattva parts instead of guessing, and adds four commands: /tattva:build, /tattva:find, /tattva:review and /tattva:theme. Pro buyers set TATTVA_LICENSE_KEY and TATTVA_API before starting Claude Code; without them the plugin stays on the free parts.New
    • Figma plugin (Downloads, For designers). It adds one theme's colours to a Figma file as variables with Light and Dark modes, and can add the corner, spacing and type-size variables and eight text styles (Geist, or Inter when Geist is not installed). Running it again with another theme updates the same variables, so switching theme is safe. It also checks a design for contrast, text size, the AI colour used as text, tap size and colours that are not Tattva colours. It is built from the same token files as the code, so the two never drift.New
    • The Connect an AI tool page now starts Claude Code users with the plugin. The single server command still works for anyone who wants only the server.Updated
    • New check for whoever builds Tattva: check:plugins runs the Figma plugin against a stand-in for Figma (adding a theme twice must update, not duplicate; a test design must trip each rule exactly where expected) and validates the Claude Code plugin and its marketplace.New
  • v0.15.1Accessibility in every theme+
    • The Accessibility guide has a new table, Results by theme: the axe check on every documentation page in all seven colour themes, in light and dark, with the date and version it ran on. Before, the checks ran in the default theme only, and a colour that passes in one theme can fail in another.New
    • DiffView: in the Terminal theme's dark mode, the line numbers on added and removed rows were 4.4:1 against the tinted background. They now use the darker grey and pass 4.5:1 in every theme.Updated
    • Four research sources had moved or gone (Vapi, Runway, ElevenLabs, a Hailuo guide). Each now links to a page that exists and says the same thing.Updated
    • New checks for whoever builds Tattva: check:a11y-matrix (every theme, light and dark), check:links (every link in the built site must resolve; outside links must answer) and check:visual (before and after screenshots of every Storybook example). The link check found that the prebuilt pages pointed downloads and Markdown links one folder too deep; that is fixed.New
  • v0.15One type scale+
    • Every text size in every part, guide and page now comes from one scale: nano, micro, small, compact, body, body-lg, lead, lead-lg, subhead, title-xs (new, 20px), title-sm and up. Tailwind's own sizes (text-xs, text-sm, text-base, text-lg, text-xl) and the old role sizes (text-note, text-label, text-row, text-input, text-answer, text-panel, text-hero) are gone from the code. Before, two size systems sat side by side, and the same 12px label could be written three ways.Updated
    • Almost nothing moves on screen. Each swap keeps the old line height by adding the matching leading-* (text-xs became text-small leading-4). Every Storybook example was screenshotted before and after: 603 of 624 are pixel-identical. StarterGallery's heading and the large Price example drop from 24px to 22px (title-sm), because the scale has no 24px step. In GlancePanel, ExportSheet, OptionChain, PermissionPrompt, OutlineEditor and VoicePanel, smaller text inside a block now takes a whole-pixel line height (20px instead of 17.14px), so a few lines move by 1 to 3 pixels.Updated
    • Code written for 0.14 or earlier still works: the old role names remain as aliases in tokens.css, marked as old. The Typography guide lists the full scale and how to swap each old name, and a new check (check:docs) fails if a Tailwind size or an old name comes back.New
    • DiffFileRow: on the selected file, the folder part of the path is now a darker grey, so it reaches 4.5:1 contrast on the selected background (it was 4.43:1).Updated
  • v0.14.2Trust and safety guide+
    • New guide, Trust and safety (Resources, Do it well). What a confidence label may and may not measure; what to show when sources disagree, only partly support a claim, fail to load or are old; who decides what between the person, your app, the model and outside content; the rules for an assistant that acts (permissions in your app, least access, untrusted content and prompt injection, ask before it counts, check again before it runs, run it once, re-sign-in, receipts, cost and loop caps, safe stop); risk beyond undo; what the closed frame for generated screens requires; and a list of attacks to try before shipping.New
    • ConfidenceIndicator's guidance now says what the level may be based on (how well sources support the answer, how much was covered, or a measured success rate), to leave it out when there is no real signal, and never to drive it from the model's own rating of itself or an unmeasured percentage. AI tools read this in components.json and through the MCP server.Updated
    • The Show your sources and Admit uncertainty patterns point to the new rules for disagreeing sources and for where confidence comes from.Updated
  • v0.14.1AI tools never invent Pro code+
    • components.json now says codeAvailable for every part, and Pro parts carry a short note: the preview and guidance are free, the code comes with Pro or Team, and an AI tool should not write its own version. Before, a Pro example simply had an empty code field, which an assistant could read as an invitation to make one up.Updated
    • The MCP server says Code: locked for a Pro part without a licence key, with the free alternative or the upgrade as the next step, instead of printing empty code blocks. Its description now says exactly what it does: reads Tattva's docs, plans a build and reviews code, and never edits your project.Updated
    • Every part's pageUrl in components.json points at its real page address (/component-<id>/), so links an AI tool shares open the right page even without JavaScript.Updated
  • v0.14State, border and inverse colours+
    • New colour tokens for selected, pressed and disabled. A chosen row, option or range now has its own selected colour, so it no longer looks like something the pointer is passing over. Disabled is one look everywhere: disabled text, fill and border colours for controls, and one shared --disabled-opacity for a whole row, instead of fading by 40, 50, 60 or 70 per cent.New
    • New border tokens for status, attention and AI boxes (success, warning, danger, info, attention and lime), plus a fainter lime wash and the lime wash's hover. New inverse colours for tooltips and value labels, and overlay and glass for controls and labels on pictures and video.New
    • Every new colour is worked out from the theme's own colours, so all seven themes, dark mode and nested light or dark previews get them with nothing to set. Parts no longer mix transparency into a colour by hand (border-danger/40, bg-lime/25, bg-fg/75); check:docs now fails if one does.Updated
    • The tap utility's invisible touch area now reaches 45px: browsers round its edges, and on a short link it came out at 43.98px, just under the 44px minimum.Updated
    • Switched to the new tokens: Button and IconButton (disabled and pressed), Switch, Select, TextField, NumberField, Checkbox, RadioGroup, Slider, Tabs, Menu, CommandPalette, ModelPicker, Tooltip, ApprovalPrompt, Badge, DataTable, DiffFileRow, ComparisonTable, BudgetControl, QuestionSet, TranscriptSync, PermissionModeSwitcher and the video and audio parts. Selected rows look slightly different (a clearer chosen state) and disabled controls are grey instead of faded.Updated
  • v0.13.1Even controls and steadier menus+
    • IconButton never shrinks in a tight row, so it stays square next to a search field or a long label. Before, a crowded header could squeeze it narrower than its height.Updated
