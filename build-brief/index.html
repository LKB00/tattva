Resources/Build brief

Build brief

Answer a few plain questions. You get one prompt to paste into your AI tool.

What are you building?
Where will it be built?
Which colour theme?
Light, dark, or both?
Which trust behaviours does the product need? (pick any)
Which plan are you on?

Your prompt

Copy it and paste it into Claude, ChatGPT, Cursor, Lovable, v0 or Bolt. It changes as you answer.

Prompt for your AI tool
I want to build: Chat assistant.

Use the Tattva design system. Read its guide first: https://lkb00.github.io/tattva/llms.txt (it links to a page for every part). Theme: lime. Mode: light and dark, following the device.

Setup:
1. If you can install packages, run npm install @tattva/ui, put @import "@tattva/ui/tokens.css"; and @source "../node_modules/@tattva/ui/dist"; at the top of the main stylesheet (they replace @import "tailwindcss";), and import every part from "@tattva/ui". If you cannot install packages, read https://lkb00.github.io/tattva/downloads/tattva-free-source.md, which holds the source of every free part in one file, recreate the parts you need under src/tattva/ with the same file names, and import from there.
2. If you used the source file, add the colours from https://lkb00.github.io/tattva/downloads/tokens.css to the project's global stylesheet. Toggle the dark class on the html element to follow the device's colour scheme.

Use these parts, in this order:
- ThreadTemplate (Pro): The page layout (Chat assistant).
- MessageList: The scrolling thread.
- Message: One turn: the person's bubble or the assistant's text.
- Composer: The message box.
- Markdown: Renders the assistant's formatting safely.
- ThinkingBlock: Shows the assistant is working, and what it did.
- TypingIndicator: A quiet sign a reply is on the way.
- SuggestionChips (Pro): Starter prompts and follow-ups.
- MessageActions (Pro): Copy, retry and rate under a reply.
- ConversationList (Pro): Past chats in the sidebar.
- ModelPicker (Pro): Lets the person choose a model.
- CitationMarker: The small numbered marker in the text.
- SourceList (Pro): The sources behind an answer.
- SourceCard (Pro): One source.
- FeedbackBar (Pro): Thumbs up and down with a reason.

Parts marked (Pro) have a free preview and guidance, but their code is not available to you. Build the screen from the free parts, and for each Pro part use a simple plain stand-in built from free parts, with a comment naming the Pro part so I can swap it in later.

Rules:
- Import parts and icons only from the tattva folder, never from a deep path (icons are named like SendIcon and CopyIcon). Never write hex colours; use the tokens (var(--surface), var(--fg)).
- The AI colour marks AI only, and is never used as text. Amber means a person has to act.
- Every button and icon has a clear name. Status is never colour alone.
- If no part fits something I ask for, tell me and ask. Do not invent parts, props or colours.

Project brief (save it as tattva.md and read it first next time):
# Tattva project brief

Saved by the Tattva MCP server. Read this first in every session so the product stays consistent.

- Product: Chat assistant
- Stack: no-code
- Theme: lime (default)
- Mode: both
- Trust behaviours: sources, feedback
- Plan: free

## Parts
- ThreadTemplate (Pro): The page layout (Chat assistant).
- MessageList: The scrolling thread.
- Message: One turn: the person's bubble or the assistant's text.
- Composer: The message box.
- Markdown: Renders the assistant's formatting safely.
- ThinkingBlock: Shows the assistant is working, and what it did.
- TypingIndicator: A quiet sign a reply is on the way.
- SuggestionChips (Pro): Starter prompts and follow-ups.
- MessageActions (Pro): Copy, retry and rate under a reply.
- ConversationList (Pro): Past chats in the sidebar.
- ModelPicker (Pro): Lets the person choose a model.
- CitationMarker: The small numbered marker in the text.
- SourceList (Pro): The sources behind an answer.
- SourceCard (Pro): One source.
- FeedbackBar (Pro): Thumbs up and down with a reason.

## Rules
- Import from the package index only.
- Use tokens (`var(--surface)`), never hex values.
- The AI colour (`--lime`) is a fill, never text. Amber means a person has to act.
- Every control has an accessible name. Status is never colour alone.
- Run `review_code` on each file before finishing.
