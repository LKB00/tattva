UsageCodeDesignAccessibility

When to use it

One headline number with how it changed. The change says "better" or "worse" in words, and you choose which direction is good, so a drop in wait time reads as good news.

Made of: Name · Action chip · Big number · Trend line · Change · Detail line · Limit scale

Use it for

  • A row of the few numbers that matter most, above the charts.
  • A number with its change since the last period.
  • A number measured against a limit or target, shown on a small scale.

Not for

  • A change over time that people need to read point by point: use LineChart.
  • Comparing several amounts: use BarChart.
  • How much of an allowance is used or left: use UsageMeter.

Do and avoid

Do

  • Say which direction is good on every tile, so lower-is-better numbers read correctly.
  • Say what the change is compared to, such as the previous 7 days.
  • For rates from small groups, show the range or group size in the detail line.
  • Put one row of tiles above the charts for the numbers that matter most.

Avoid

  • Don't use amber for a number that just got worse. Amber means a person must act.
  • Don't rely on color for the change. The arrow, the plus or minus and the word "better" or "worse" carry the meaning.
  • Don't draw a chart with one bar when a tile says it.
  • Don't add labels to the trend line. The tile's number and change say it.

On a phone

  • The tile fills the width of its container and the value breaks onto a new line instead of overflowing.
  • The sparkline stays at its own size on the right and the text on the left shrinks first.
  • Nothing in the tile needs hover or a tap.

Seen in products

  • Company blogs about monitoring AI products show dashboards with slowest response times, volume, cost per model and error rate, and treat time to the first word as a key measure.
  • They list typical and slowest response times by model with a count of requests, and quality measures such as test pass rate and user feedback.
  • Carbon's dashboards guidance prioritizes data by hierarchy.
  • OneUptime, LLM observability dashboard (opens in a new tab)
  • Requesty, LLM observability metrics (opens in a new tab)
  • SigNoz, AI observability (opens in a new tab)
  • Carbon chart anatomy (opens in a new tab)

States

States this part has beyond its default look. Build each one your screen can reach. States set by a property are in the Code tab.

better
When the delta direction matches goodDirection, the change is shown in green with the word better.
worse
When the delta direction is the opposite of goodDirection, the change is shown in red with the word worse.
flat or neutral
A flat change, or goodDirection set to neutral, is shown in the muted colour with no verdict.
needs action
Pass needsAction to add an attention tag and turn the threshold bar to the warning colour.
threshold
Pass threshold to show a meter bar with a marker at the limit and its label below.

Tokens

Change one of these and every part that uses it follows.

  • --success-fg
  • --danger-fg
  • --attention-soft
  • --attention-fg
  • --fg
  • --fg-muted
  • --border
  • --radius-control
  • --radius-card

Built in

  • Each tile is a group named by its label.
  • Screen readers hear the change as a direction word, such as "up", then the amount and "better" or "worse".
  • The arrow is hidden from screen readers. Color only repeats what the words say.
  • The limit scale is a meter, read with the value and the limit's label.

What you need to do

  1. 1Set goodDirection on every tile where lower is better, or a drop is called "worse".
  2. 2Say what the change is compared to in versus, such as "vs previous 7 days".
  3. 3Pass a trend line with decorative set, so screen readers do not hear the numbers twice.

Built toward WCAG 2.2 AA and checked automatically; no independent audit yet. Read the accessibility guide
